Fields Restriction

Choose the fields available to everyone, specific groups or individual users.

Export & Import Filters Group By

Manage Export and Import with one shared field policy. Configure Filters and Group By separately. Apply rules by model to everyone, a group or selected users, with optional Menu and Action settings.

Features

OperationWhat is controlled
Export & Import

Choose which fields users can export and import. Restricted fields are hidden from export field choices and import mappings. The same policy applies to saved templates, CSV/XLSX downloads and checks before Test or Import.

Example: For Sales Orders, allow only Order Reference and Salesperson. Users can export and map those fields, while Customer is unavailable for both operations.
Filters

Choose which fields users can filter records by. Restricted fields are hidden from Add Custom Filter. Built-in filters, date filters and favorites that use those fields are also hidden. Allowed default filters stay active.

Example: For Sales Orders, allow only Order Reference and Salesperson. Users can filter by those fields, while filters using Status or Creation Date are hidden. My Quotations remains available in the standard view.
Group By

Choose which fields users can group records by. Restricted fields are hidden from Add Custom Group. Predefined Group By options that use those fields are also hidden. This policy is independent of Filters.

Example: For Sales Orders, allow only Customer. Users can group by Customer, while grouping by Salesperson or Order Date is unavailable.

Supports standard and custom fields. Field selectors show labels and technical names, with choices filtered by the operation they support.

Set up your first rule

  1. Open the configuration. As a Settings administrator, enable developer mode and go to Settings > Technical > Database Structure > Fields Restriction Rules. Click New.
  2. Name the rule and select a Model. Menu and Action are optional. Selecting a Menu fills its Action and limits the choices. With Menu empty, all actions for the model are available. Leave both empty for a model-wide rule.
  3. Choose Apply To and Priority. Select Global, Group or User, then choose the targets when needed. The defaults are Global and Priority 1. Set Priority manually to resolve conflicting field rules.
  4. Select policies and fields. Configure the Export / Import, Filters and Group By tabs. Save and reload the target user's browser. Export and Import share one policy and field list.
PolicyBehavior
No restrictionAdds no field decisions. Other matching rules still apply.
Only selected fieldsAllows selected fields. Allowances from matching rules are combined, then conflicts are resolved per field. Unlisted fields remain hidden.
Block selected fieldsBlocks selected fields, subject to the per-field priority rules below.

An empty allowlist adds no allowed fields and does not erase another rule's selections. User or Group rules with no targets do not apply to anyone.

Example: one model, two actions

Use two Global rules for Sales Order, both at Priority 1, with Export / Import set to Only selected fields.

ActionSelected fields
QuotationsOrder Reference (name) and Salesperson (user_id)
Sales OrdersOrder Reference (name) and Customer (partner_id)

Each action uses its matching rule. An Action-only rule follows that action across menus. Select Menu to distinguish menus that share one action. Menu rules apply to the exact originating menu.

How rules combine

All active rules matching the model, audience and optional Menu / Action are considered. Decisions are made separately for Filters, Group By and Export / Import.

SituationResult
Different fieldsCombine the selections, even when Priority or Apply To differs.
Same field, conflicting decisionsThe smaller Priority number wins.
Same field and PriorityUser takes precedence over Group, then Global.
Same field, Priority and Apply ToA block wins over an allowance.

Example: allowing name, email in one rule and name, phone in another makes all three fields available. If a winning rule blocks email, only name and phone remain.

Priority resolves conflicts for shared fields only. Menu or Action specificity does not change that order. Archived rules are ignored.

Usage notes

  • Without a matching active rule, no rule-based field restrictions apply. Administrators follow matching rules too. Superuser mode bypasses them.
  • Odoo field capabilities still apply. Exportable read-only fields may not support import, and required fields need values or defaults. Related fields also follow their target model's rules.
  • This module controls field choices and web Export / Import. It does not hide form or list columns, replace access rights, or restrict direct ORM/API operations.
